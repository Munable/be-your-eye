# 让另一台手机收到提醒

[English](PAIRING.md) · [使用说明](../../USER_MANUAL.zh-CN.md) · [构建与安装](BUILD.zh-CN.md)

**A 手机负责监控，B 手机负责提醒你。** 跨手机提醒需要两端安装 Community 应用并联网。只有监控端需要识别模型及其支持的硬件。

应用安装要求 Android 8+ 和 arm64。当前识别模型要求监控端有 8 GB 内存；单纯接收文字不加载这些模型。已记录的收信测试使用 4 GB 模拟器，尚不是真机兼容性测试。目前没有公开 APK，真机配对与持续送达仍待验证，详见[设备范围](DEVICE_SUPPORT.zh-CN.md)。

| 在 A 手机上 | 在 B 手机上 |
| --- | --- |
| 打开“关于 → 配对手机 → 创建配对组” | 打开“关于 → 配对手机 → 扫描配对二维码” |
| 确认中转地址，再显示二维码 | 扫描 A 的码并确认中转地址 |
| 不向无关人员展示二维码 | 允许通知，点击“开启收信” |
| 点击“发送测试提醒” | 在收件箱和系统通知栏确认收到新提醒 |
| 为实际监控开启通知，并开始监控 | 保持收信开启，按页面提示调整电池限制 |

不方便扫码时也可以复制配对码加入。扫码和监控都要使用相机，因此应先停止监控再打开扫码。更多手机也可以加入同一个组。配对不需要帮你盯账号、API Key、端口转发或维护者服务器。

## 发送的内容

一条小型**加密文字消息**包含监控名称、事件类型、时间，以及数字事件的显示读数。不发送照片、缩略图、实时视频或远程相机命令。接收端收件箱保留最近 200 条提醒；监控端保留自己的图像和完整本机历史。

二维码内含群组加密密钥，只能分享给信任的人。每个成员都能收发群组提醒。要移除一个成员，需要解除配对并创建新组，只让其余手机重新加入。解除某台手机的配对，无法删除其他人已经复制的密钥。

## 免费公共中转及其限制

默认使用 [ntfy.sh](https://ntfy.sh)，这是独立的公共服务，不是帮你盯运营的服务器。消息匿名发布，应用在发送前使用 AES-256-GCM 加密；中转运营者仍能看到 IP 地址、随机主题、时间和消息大小。创建组时可选择另一个兼容、允许匿名使用的 HTTPS ntfy 地址。项目不提供托管、账号、API Key、付费订阅或自动付费兜底。

实现时，ntfy.sh 的[公开免费额度](https://docs.ntfy.sh/publish/)包括每天 250 条消息、单条 4,096 字节；共享 IP 可能共享额度。额度、保留时间和可用性会改变，不承诺任何服务永久免费或始终可用。请发送少量有意义的事件提醒，而不是连续上传每次读数。

开启收信后，应用会显示常驻通知。Android 电池限制、强制停止、断网、中转不可用或限流都可能导致延迟或丢失。重连时，接收端请求最近最多 24 小时仍被保留的缓存消息；中转从未接收或已经删除的消息无法恢复。重启或强制停止后，需要重新打开应用并开启收信。“已发送”只表示中转接受了消息，真正送达需要在另一台手机上确认。

监控和收信的生命周期不同：**监控手机锁屏会停止相机**；单独主动开启的文字接收服务可以继续在后台运行。两者都不适合作为安全报警器。

协议细节和信任边界见[架构（英文）](../ARCHITECTURE.md)。

收件箱保留 200 条提醒，去重用的接收 ID 最多保留 2,000 条。达到容量后，持久化的时间下限会拒绝更早的延迟消息，避免再次显示已处理的提醒；重启应用会保留这个下限。这也是跨手机提醒只能视为尽力送达的原因之一。
